## Test type

Integration. Mocked Node/Worker tests for protected staging readiness and failure handling. Live OAuth execution belongs to owner-operated #141.

## What needs to be tested?

### Problem and context

Staging scripts validate secret-name pairing but do not structurally validate the service account or obtain an OAuth token as a readiness check. Owners cannot distinguish a present secret from usable provider credentials. Runtime parsing also currently expects camel-case credential fields rather than Firebase's standard document shape.

### This ticket aims to

Provide a tested, protected OAuth-only readiness command and sanitized artifact for [the release specification](../spec.md), without sending notifications or using real credentials during development.

## Test cases

- [ ] Safely parse/normalize the standard Firebase service-account shape, validate required fields without printing them, and mint/request an OAuth token using mocks in tests.
- [ ] The readiness command has no FCM message-send operation. Unexpected/failed provider responses become sanitized categories, never raw bodies or secrets.
- [ ] Missing credentials preserve the no-push deployment path. Malformed configured credentials stop push enablement while existing foreground REST/realtime stays available.
- [ ] Validate the encryption-key binding name only. Never read, generate, overwrite, fingerprint or expose its value.
- [ ] Integrate through the existing manual main-only protected staging workflow. Preserve secret allowlist and no routine push-key sync.
- [ ] Artifact contains only commit/build metadata, check categories, timestamps and pass/fail, with negative tests for credential/token/project-ID leakage.
- [ ] Prove omission of a source secret does not imply Worker deletion; document feature-flag rollback and partial-secret-sync failure handling.
