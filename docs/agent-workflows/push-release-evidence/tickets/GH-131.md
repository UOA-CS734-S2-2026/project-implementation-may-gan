## Outcome

### Problem and context

The issue records earlier local/CI checks and no-push staging rollout, but these do not prove authenticated phone-to-browser recovery, physical push or latency. Release owners need actual evidence before making those claims.

### This ticket aims to

Act as the final next-release evidence gate in [the release specification](../spec.md), preserving history and recording functional, privacy, performance and rollback results.

## Dependencies

GH-130. GH-141 and notification implementation are transitive. Completed #128, #29, #30, #31, #33 and #47 remain historical foundations, not reopened blockers. GH-255 is independent and non-blocking; record its residual risk if still unshipped. Quiet hours remains a separate non-blocking follow-up.

## Scope

Full regression evidence, deployed two-user browser/mobile journeys, recovery/no-polling, physical notification evidence, measured latency and operational observations, additive rollout, feature disablement and failed-job handling.

## Exclusions

No provisioning, secret writes, production deployment, duplicate notification implementation or issue closure based on local tests alone.

## Acceptance criteria

- [ ] Record local regression, Worker realtime, generated-client equality and migration verification against the actual candidate SHA. Hosted verification is not assumed available.
- [ ] Prove deployed authenticated browser/mobile journeys plus actor second-session sync, reconnect/catch-up, older edits/unsends, no periodic polling, logout and account-switch isolation.
- [ ] Consume GH-130 sanitized physical Android/iOS results for all four notification categories and preview/tap policy.
- [ ] Document synthetic two-user workload, sample size, measurement method, candidate/build, and staging commit-to-visible p95. Missing measurement or p95 above two seconds blocks release.
- [ ] Record outbox age/recovery, reconnect observations, SQL-plan findings and cost drivers without inventing unapproved capacity thresholds.
- [ ] Verify additive rollout and notification-feature disablement while accepted messages and REST/realtime remain usable. Document safe failed-job handling and log-redaction observations.
- [ ] Record remaining external blockers, GH-255 status/residual risk, and quiet-hours follow-up. Failed privacy/device/performance gates stay unchecked.

## Edge case

An expired/replaced session taps a stale notification after a reconnect. It cannot restore credentials or render old private cached content.

## Entry points

`docs/implementation/messaging-verification.md`, `docs/implementation/staging-deployment.md`, automated suites, deployed observability and sanitized evidence artifacts.

## Validation

`pnpm verify:local`, Worker realtime checks, approved deployed journeys and timing instrumentation, and GH-130 evidence review. Missing tooling/access is unverified, not a pass.

## Risk and rollback

Abort release or disable notifications with the feature flag. Preserve storage, REST/realtime, encryption key and deployed migration history. Evidence/PR merge alone does not activate a deployment.
