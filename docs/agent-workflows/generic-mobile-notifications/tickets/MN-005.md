# MN-005: Notify eligible users when friends posts release at Auckland midnight

Status: approved ticket scope. Execution is governed by `../run-approval.md`.
Template: `.github/ISSUE_TEMPLATE/feature.yml`. Proposed label: feature.
Merge mode: auto-merge, subject to CI, local verification, independent review and repository protection.

## Description

### Problem and context

Friends-audience posts become readable at midnight, but no mobile release notification exists. Users receive no signal that authorized posts are available. Evidence: current scheduled Worker only repairs delivery; post release is enforced by timestamps and visibility predicates.

### This ticket aims to

Send one fixed-content release notification per eligible recipient and Auckland release date through [the notification specification](../spec.md).

## Scope and exclusions

Reuse GH-034 scheduling, add release eligibility/deduplication/expiry, dispatch recheck, and permission-equivalent recipient queries. Exclude changing release/access policy, notifying per post, quiet hours, and new feed UI.

## Acceptance Criteria

- [ ] At 00:00 Auckland time, the event identity uses the recipient, release category, and Auckland release date. Source posts are from the preceding posting day and have reached that release boundary.
- [ ] Queue only when at least one newly released friends-audience post is readable under current friendship, block and account/content availability rules. Solo, unavailable and unauthorized posts never qualify.
- [ ] Recheck that at least one qualifying post is still authorized at dispatch. Changed friendship, block, post deletion/availability or opt-out can suppress delivery.
- [ ] Persistent event/destination uniqueness and bounded scheduler progress tolerate retries, concurrent cron and recovery. Release notices expire at the next Auckland midnight; do not backfill earlier days.
- [ ] Fixed wording discloses no friend identity or post text; typed tap target is the friends feed.
- [ ] DST, empty feed, ended friendship, blocked author, repeated scheduling, late recovery and expiry tests pass.

## High Risk?

Timezone/release enforcement, post visibility and notification fan-out. Do not import obsolete Firebase Auth, GraphQL, E2EE or FCM topic assumptions.
