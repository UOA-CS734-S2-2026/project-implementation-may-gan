## Goal

### Problem and context

Users who have not posted receive no durable server closing reminder. Existing #34 combines closing/unlock reminders with undefined quiet hours. The approved spec defines the daily event time and eligibility; the user approved splitting quiet hours into a blocked follow-up.

### This ticket aims to

Send an eligible opt-in user one final-hour notification for the current Auckland posting day through [the shared notification specification](../spec.md).

## Scope

Create bounded server daily scheduling infrastructure and the 23:00 reminder publisher. Deduplicate by recipient, event kind and posting date. Recheck eligibility before dispatch and expire reminders at the next Auckland midnight. Preserve old #34 history and link MN-QH-001 as deferred quiet-hours scope.

## Out of scope

Midnight release publisher, owned by MN-005; quiet hours, owned by blocked MN-QH-001; device-local timers; additional reminders or per-category settings.

## Acceptance criteria

- [ ] Server schedule uses Pacific/Auckland calendar arithmetic and server time. No client clock determines eligibility.
- [ ] From 23:00 until that posting day's midnight, only opted-in users without an accepted post are eligible. Existing accepted solo posts count as posted.
- [ ] Bounded, resumable recipient batches tolerate concurrent cron invocations/restarts without duplicate recipient/day events or starving later pages.
- [ ] Dispatch suppresses if the user has posted, opted out, lost session/device eligibility, or the event expired. Recovery after midnight never sends yesterday's reminder.
- [ ] DST, midnight boundaries, repeated cron, restart, concurrent posting, and denied-permission cases pass.
- [ ] Fixed daily copy has no private content. Notifications do not gate posting/feed access.
