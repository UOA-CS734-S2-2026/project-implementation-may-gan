# Self-service export inventory, draft baseline

This is the source inventory for the single export service in #162, shared with #64, #65, and #66. It is not an active export implementation or approval to release user data. The machine-readable decisions are in `packages/db/src/export/inventory.ts`. The schema check lists every current table and column, compares them to the migrated PostgreSQL schema, and fails if a new column is not classified. A checked-in decision never automatically adds a field to an archive.

## Inclusion boundary

The planned owner-scoped sources are profile fields, owned active posts and revisions, post media and avatar metadata, private notes, currently readable authored messages, minimal Terms and age evidence, and still-restorable posts and media metadata under `trash/`. Post and avatar upload bytes are in scope only when a source procedure independently proves the owner, live post or avatar link, reservation, and exact R2 object key. Merged PR #252 adds restricted file reads and an archive worker that remains disabled. Local CI uses synthetic database and provider fixtures; a separate test on 2026-10-03 exercised synthetic multipart, range, abort, listing, and delete operations against a dedicated empty R2 bucket. It did not use account content or test the full production Worker. Message authorship alone does not authorize an export: the requester must also retain normal readable-history access at each page. Blocks do not erase readable history. Received bodies and reply previews are excluded. Authored comments follow the same rule against their post: the archive may list a person's own comment bodies, edit and deletion times while they can still read the post, but not reply pointers, who deleted a comment, or other people's comments. Likes are excluded with message reactions, because the list of likers on someone's post is other people's identity data. Content resembling a URL stays unchanged; internal signed URLs and R2 keys are never emitted as record fields.

The `post_revisions.previous_attachment_refs` JSON family is not exported as an arbitrary blob. Only `media_id`, `attachment_order`, and `status` may appear after validation. The schema and migrated-database tests census every JSON and JSONB column. Every transformed JSON family must register exact keys, a SQL validator identifier, and valid and extra-key fixtures exercised against migrated PostgreSQL. The current `public.dayli_attachment_refs_valid(jsonb)` contract accepts the reviewed three-key form and rejects an extra key. The registered object namespaces are `media/` and `private/data-exports/v2/`. Media reservations use the shared `buildOwnedMediaObjectKey` constructor. The upload presigning sink validates the owned-media namespace even for aliased or inline arguments. The lint check rejects literal assignments to `objectKey` or `archiveObjectKey` and direct `.put()` object-store calls in API and database source files, including aliased keys. This does not prove ownership of a stored object, protect arbitrary future storage APIs, or grant permission to write a private archive. The archive writer reserves a database-derived private key and cleanup task before multipart initiation. Independent review and a separate synthetic live R2 adapter proof have passed; neither authorizes production execution. A new namespace, JSON key family, table, or column requires its own inventory entry, source review, and positive or negative fixture before the service can be declared complete.

Authentication storage, secrets, push tokens, sessions, grant and OAuth state, logs, lifecycle control data, recipient identities, received messages, request fingerprints, raw legacy Cloudinary URLs, and operator cases are excluded from the self-service ZIP. Their exclusion does not settle a separate formal access request. Recipient-held conversation history and reactions survive a sender's deletion under the messaging retention decision, but the sender's archive cannot include another participant's private content. Friend requests, friendships, and blocks are excluded from this ZIP; their reviewed relationship-state decision removes the relationship record when either account is permanently deleted. Friend requests may persist while both accounts exist for request throttling. This decision does not authorize bypassing the existing deletion procedures.

## Retention and provider boundary

Account content remains subject to its own account and post Trash deadlines. A Trash item may enter `trash/` only while database time is strictly before its original restore deadline. Exports do not pause or extend a deletion. Ready archives expire after 24 hours, and purge takes precedence. Merged PR #252 adds durable archive cleanup ownership, a second provider reconciliation pass after 24 hours, and content-free incident evidence retained until 30 days after resolution. Live-provider late-completion recovery remains unverified.

Dayli-controlled diagnostic and security logs have a 30-day maximum under #157. Minimal unresolved cleanup evidence expires 30 days after resolution. The separate content-free purge receipt expires 30 days after cleanup completion. Cloudflare, R2, Google, and delivery-provider retention cannot be inferred from PostgreSQL; verify live provider settings separately. No provider objects, raw logs, archive URLs, or credentials are made exportable by this inventory.

## Verification still required

The inventory unit test checks exact Drizzle tables and fields, JSON key families, the object-key constructor, and named inventory canaries. The database check confirms every referenced test name exists in the checked-in test registry and source file. The PostgreSQL test compares the inventory with the migrated `public` schema, including handwritten migrations, and executes the registered SQL validator for each transformed JSON family using both fixtures. The inventory canaries alone test decisions, not ZIP content or row-level authorization. Merged PR #252 includes synthetic source, ZIP, lease, download, client, and provider-failure tests. Its independent review and exact-head CI passed, and a separate synthetic proof exercised the R2 adapter against an empty dedicated bucket. Physical device sharing, production configuration, delayed provider completion, and the final activation decision remain separate checks. This inventory does not authorize an export worker or public release.
